Как превратить ChatGPT в агента

Я часто ловил себя на простой мысли: ChatGPT уже умеет очень много, но интерфейс всё ещё похож на один длинный чат. А мне хотелось не чат, а рабочее место.

Чтобы слева один диалог писал код, справа другой проверял результат, третий держал контекст, а я в это время мог накидать очередь следующих шагов и уйти пить чай. Если задача закончилась — пусть прилетит сообщение в Telegram.

Так появился мой экспериментальный Chrome-плагин ChatGPT Multi Pane.

GitHub: https://github.com/megamen32/chatgpt-multi

Это не «свой ChatGPT» и не попытка заменить официальный интерфейс. Это оболочка поверх обычного chatgpt.com: несколько живых панелей, очередь промптов, авто-подтверждение действий, сворачивание старых сообщений и маленький агентный цикл из двух чатов.

Зачем вообще превращать чат в агента

Обычный сценарий выглядит так:

  1. пишешь задачу;
  2. ждёшь ответ;
  3. читаешь;
  4. замечаешь, что не хватает детали;
  5. пишешь уточнение;
  6. повторяешь.

Это нормально для разговора. Но если задача большая, то начинаешь сам выполнять роль диспетчера: проверять, допинывать, переносить ответы между вкладками, следить, закончил ли чат генерацию.

Мне захотелось вынести часть этой рутины в интерфейс.

Идея была такая: пусть один чат будет исполнителем, а второй — проверяющим. Я задаю цель, исполнитель делает работу, проверяющий смотрит на результат и говорит: «готово» или «вот что ещё надо исправить». Если не готово — замечание автоматически отправляется обратно исполнителю.

Получается очень простой агентный цикл:

while (!done && round < maxRounds) {
  const answer = extractFinalAnswer(executorChat);
  const verdict = await askEvaluator(goal, answer);

  if (verdict.includes('GOAL REACHED GOAL')) break;

  await sendToExecutor(verdict);
  round++;
}

Конечно, это не волшебный AGI. Это скорее честный костыль поверх браузера. Но костыль оказался полезным.

Несколько ChatGPT рядом

Первое, что я сделал, — страница расширения с несколькими iframe:

<iframe src="https://chatgpt.com"></iframe>
<iframe src="https://chatgpt.com"></iframe>

И почти сразу стало понятно: если просто открыть несколько ChatGPT рядом, браузер начинает грустить. ChatGPT — тяжёлое веб-приложение. Несколько активных iframe быстро съедают память и CPU.

Поэтому появилась механика lazy panes. В каждый момент реально загружена только активная панель, остальные могут «спать»: показывают заголовок и URL, но iframe выгружен.

Когда кликаешь по панели — она снова оживает.

Это выглядит мелочью, но без неё расширением неприятно пользоваться.

Content scripts внутри iframe

Самая частая боль в таких расширениях — контекст выполнения.

Обычный content script может прекрасно работать на chatgpt.com, а потом внезапно не работать внутри iframe, который открыт на странице расширения. Лечится это настройками в manifest.json:

{
  "matches": ["https://chatgpt.com/*", "https://chat.openai.com/*"],
  "all_frames": true,
  "run_at": "document_idle"
}

Без all_frames: true часть логики просто не попадает туда, где она нужна.

Через content scripts я отслеживаю:

  • текущий URL чата;
  • заголовок;
  • состояние генерации;
  • кнопку отправки;
  • диалоги подтверждения;
  • старые сообщения, которые можно свернуть.

А внешняя страница расширения уже собирает из этого нормальный workspace.

Очередь промптов

Вторая вещь, без которой я теперь не хочу жить, — очередь промптов.

Пока ChatGPT отвечает, можно заранее добавить следующие сообщения. Когда генерация закончилась, расширение само отправляет следующий промпт.

Это удобно для длинных задач:

  • «сначала найди проблему»;
  • «теперь предложи фикс»;
  • «теперь напиши тесты»;
  • «теперь сделай короткий отчёт».

Модель очереди вынесена в чистый JS-модуль, чтобы не тестировать её через браузер:

queue.add('найди баг');
queue.add('предложи фикс');
queue.add('напиши тесты');

const next = queue.shift();

Вообще это главный урок проекта: всё, что можно вынести из content script в обычную функцию, лучше вынести. Иначе через неделю сам не поймёшь, где у тебя логика, а где шаманство с DOM.

Auto-confirm для Custom GPT Actions

Когда отлаживаешь Custom GPT с actions, ChatGPT постоянно спрашивает подтверждение. Это правильно с точки зрения безопасности, но при разработке мешает.

Я добавил режим auto-confirm: расширение ищет диалог и кликает Confirm/Allow.

Там есть нюанс: интерфейс может быть на разных языках. Поэтому нельзя просто искать кнопку Confirm. Пришлось нормализовать текст и учитывать разные варианты, включая Allow и Разрешить.

Сразу оговорка: я бы не советовал держать такую функцию включённой постоянно. Это инструмент для отладки, а не режим «соглашаться со всем в интернете».

Старые сообщения надо сворачивать

Длинные чаты тормозят. Особенно если там много markdown, кода и tool calls.

Поэтому я добавил auto-collapse: старые сообщения сворачиваются, а видимыми остаются последние N. Плюс есть более агрессивная оптимизация — trim больших ответов conversation API, чтобы ChatGPT не пытался переварить слишком много старого контента при загрузке.

Это самая хрупкая часть, потому что внутренности ChatGPT могут поменяться в любой день. Но когда работает — длинные чаты становятся заметно легче.

Goal Agent

Самая интересная часть — режим Goal Agent.

Схема простая:

  • выбираем панель-исполнитель;
  • выбираем панель-проверяющий;
  • пишем цель;
  • исполнитель делает задачу;
  • проверяющий оценивает только финальный ответ;
  • если цель не достигнута, его замечания отправляются обратно исполнителю;
  • если достигнута, он пишет маркер GOAL REACHED GOAL.

Почему проверяющий получает только финальный ответ? Потому что если скормить ему всю историю, tool calls и промежуточные куски, он часто начинает оценивать не то. Ему нужен результат, а не весь шум процесса.

Да, иногда оно зацикливается. Да, иногда проверяющий слишком строгий. Да, иногда исполнитель спорит с замечаниями. Поэтому есть лимит итераций и ручная остановка.

Но для некоторых задач это реально экономит внимание. Особенно когда нужно не просто получить ответ, а довести его до состояния «можно использовать».

Telegram как пульт

Ещё я добавил Telegram bridge. Он нужен для длинных прогонов: отправил задачу, ушёл, получил финальный отчёт в Telegram.

Service worker расширения long-poll'ит Telegram Bot API, режет длинные сообщения на куски до 4096 символов и умеет пересылать ответы выбранной панели.

Это не самая красивая архитектура, но для личного инструмента очень удобно.

Тесты

Я не стал тестировать всё через браузер. Вместо этого вынес чистую логику в модули и покрыл её node:test.

Сейчас тестируются:

  • очередь;
  • состояние панелей;
  • trim conversation;
  • goal loop;
  • Telegram chunking;
  • matcher для confirm-кнопок;
  • collapse старых сообщений.

Последний прогон:

94 tests
94 pass
0 fail

Для Chrome-расширения это не идеальная гарантия, но лучше, чем держать всю логику в одном огромном content script и молиться.

Что в итоге получилось

Получился не продукт «для всех», а скорее рабочий инструмент для себя:

  • несколько ChatGPT рядом;
  • спящие панели, чтобы не убивать браузер;
  • очередь промптов;
  • авто-подтверждение actions;
  • сворачивание старых сообщений;
  • простой агентный цикл;
  • Telegram-уведомления;
  • тестируемая логика.

Главный вывод: чтобы превратить ChatGPT в агента, не обязательно сразу писать отдельный backend, свой браузер и сложный orchestration framework. Иногда достаточно начать с интерфейса: дать чату память о панелях, очередь действий и второго «проверяющего».

Это всё ещё хрупкий слой поверх чужого UI. DOM меняется, кнопки переезжают, внутренние API могут сломаться. Но как личный инструмент — работает surprisingly well.
